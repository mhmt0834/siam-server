# 售后排查手册

## 排查顺序

1. 确认故障商家、`shopId`、发生时间、订单号或桌号。
2. 检查 `/actuator/health`、MySQL、Redis、HTTPS 证书与请求域名。
3. 只查看相关服务日志，禁止输出支付密钥、证书、手机号全量或用户隐私数据。
4. 复现最小流程，区分商家配置、网络、微信平台和代码问题。

## 常见问题

### 扫码无效

- 检查桌码 `sceneToken` 是否存在、餐桌是否启用、是否属于当前店铺。
- 重新生成场景码后，旧码应按产品规则作废。

### 菜单或购物车混店

- 确认接口从 Token/场景码解析店铺，不使用前端提交的 `shopId` 授权。
- 核对购物车的 `shop_id`、`dining_table_id`、`member_id`。

### 支付失败

- 只检查该订单店铺的“配置是否完成”和掩码信息。
- 核对 AppID、商户号、回调域名、证书有效期和订单金额；不要复制密钥到聊天或日志。
- 重复回调应幂等，不得重复记账或重复通知。

### 老板收不到订单

- 确认订单状态已由待支付变为待接单。
- 检查 WebSocket 店铺频道；断线时确认轮询仍在刷新。
- 检查浏览器自动播放限制及新订单声音开关。

### 经营统计不变化

- 统计只包含状态为已完成且存在完成时间的订单。
- 核对订单 `shop_id`、完成时间和实付金额，不使用未支付或已取消订单。

### 批量导入失败

- JSON 单次不超过 500 条，名称、图片、分类和正价格必填。
- Excel 必须为 `.xlsx` 且包含规定表头及嵌入图片。
- 先修复返回的首个错误行，再重新导入；事务失败不会写入菜品记录。

## 升级处理

无法在 30 分钟内定位时，保存脱敏后的错误时间、接口、状态码和最小复现步骤，回到对应稳定 Git 标签对比。未经商家授权不得直接修改生产订单、支付记录或用户数据。

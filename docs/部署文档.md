# 部署文档

## 基线与环境

- 代码基线：`restaurant-saas-v1.4-statistics` 之后的商业交付版本。
- 服务端：JDK 8、MySQL、Redis、Maven。
- 平台管理端：Node.js 18（当前 `node-sass 9`）。
- 老板端：Node.js 12（遗留 `node-sass 4.13.1`）；升级依赖前不要与管理端共用 Node 运行时。
- 小程序：HBuilderX CLI、微信开发者工具及商家授权的正式 AppID。

## 复制门店实例

每个商家从母版复制独立目录和独立部署配置。先验证参数，不写文件：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/prepare-merchant-delivery.ps1 `
  -ProjectRoot "C:\merchant-instance" `
  -RestaurantName "示例餐厅" -Slogan "认真做好每一餐" `
  -DCloudAppId "__UNI__INSTANCE" -WechatAppId "wx0000000000000000" `
  -DefaultShopId 100 -ApiBaseUrl "https://api.example.com/siam-server" `
  -RequestDomain "https://api.example.com"
```

商家确认公开资料后，在门店实例目录增加 `-ApplyConfiguration -MerchantApproved`。只有商家完成支付配置确认时才允许同时使用 `-EnableWechatPay -MerchantPaymentConfirmed`。

## 服务端配置

- MySQL、Redis、HTTPS API、回调域名使用部署环境变量或受管配置。
- AppSecret、APIv3 Key、商户私钥和证书只放服务端密钥环境；不写入仓库。
- 每个支付请求按订单 `shop_id` 读取对应商户配置，平台不代收资金。

## 构建与预检

```powershell
powershell -ExecutionPolicy Bypass -File scripts/check-secrets.ps1
powershell -ExecutionPolicy Bypass -File scripts/build-all.ps1 `
  -HBuilderCli "C:\HBuilderX\cli.exe" `
  -AdminNodeBin "C:\runtime\node18" -MerchantNodeBin "C:\runtime\node12"
powershell -ExecutionPolicy Bypass -File scripts/preflight-release.ps1 `
  -RequireBuildArtifacts -HealthUrl "https://api.example.com/siam-server/actuator/health"
```

`build-all.ps1` 会构建平台管理端、老板端和微信小程序。上传前还需在微信开发者工具检查 Console、包体积、请求域名和真机流程。

## 发布与回滚

- 商家确认最终预览后，授权管理员只执行上传；提审、发布和支付启用需单独授权。
- 保留对应 Git 标签、数据库迁移记录和部署参数清单（不含密钥）。
- 回滚优先切换到上一稳定标签并恢复匹配的数据库结构，不使用破坏性 Git 命令覆盖未备份修改。
